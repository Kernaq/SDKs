# Contributing to Kernaq SDKs

Thank you for your interest. External contributions are welcome via Pull Requests.

## Process

1. Fork the repository
2. Create a branch: `git checkout -b fix/your-fix-name`
3. Make your changes
4. Open a Pull Request against `main`

## Rules

- All PRs require review and approval from a Kernaq maintainer before merge
- No one can push directly to `main` — all changes go through PRs
- PRs that add, modify or remove functionality must include tests
- The CI workflow must pass before a PR can be merged

## Security

If you find a security vulnerability, **do not open a public issue**.  
Email security@kernaq.com directly.

## What we accept

- Bug fixes
- Improved documentation
- Additional language support
- Test coverage improvements

## What we do not accept

- Changes to published package versions
- Changes to the GitHub Actions publish workflows without prior discussion
- Breaking API changes without an issue discussion first
